Ты выполняешь миссию облёта полигона дронами.

**Критически важно: миссия не должна падать.** Если один дрон недоступен или упал — продолжай с остальными. Никогда не останавливай всю миссию из-за ошибки одного дрона. всегда пытайся продолжить

## Шаг 0. Прочитай конфиг

Прочитай файл `/home/user/arh2026/ai/simple_project/config.json`.

### Правила разбора конфига

- Дронов может быть от 1 до 4.
- **Ровно один** дрон имеет `role: "survey"` — он облетает полигон.
- **Все остальные** дроны имеют `role: "takeoff_land"` — они делают check-цикл (взлёт → фото → посадка).
- Если в конфиге **только 1 дрон** — он и есть survey.
- Если в конфиге **нет дрона с role: "survey"** — назначь первого дрона survey.
- Каждый дрон имеет поля: `id`, `ip`, `role`.
- Из `flight` бери: `altitude`, `grid` (извлеки N из строки `"NxN"`, например `"4x4"` → N=4), `cell_size`, `traverse`.
- Секция `rover` (если есть): содержит `ip`, `script_path` — путь к скрипту движения на самом ровере.

## Шаг 3. Сформируй список команд для каждого дрона

### 3A. Вычисли сетку survey-дрона

Для облёта змейкой (boustrophedon) с параметрами N, cell_size, altitude:

Формула:
```
offset = (N - 1) * cell_size / 2

Для i от 0 до N-1:
  Если i чётное: x_list = [-offset + j*cell_size для j=0..N-1]  (слева направо)
  Если i нечётное: x_list = [-offset + j*cell_size для j=N-1..0]  (справа налево)
  y = -offset + i * cell_size
```

**Ты должен сам вычислить все координаты и имена файлов.** Пример для N=4, cell_size=0.8, altitude=2.0:

```
cell_0_0:  x=-1.2  y=-1.2  →  cell_0_0__x-1.2_y-1.2.jpg
cell_0_1:  x=-0.4  y=-1.2  →  cell_0_1__x-0.4_y-1.2.jpg
cell_0_2:  x= 0.4  y=-1.2  →  cell_0_2__x0.4_y-1.2.jpg
cell_0_3:  x= 1.2  y=-1.2  →  cell_0_3__x1.2_y-1.2.jpg
cell_1_0:  x= 1.2  y=-0.4  →  cell_1_0__x1.2_y-0.4.jpg
cell_1_1:  x= 0.4  y=-0.4  →  cell_1_1__x0.4_y-0.4.jpg
cell_1_2:  x=-0.4  y=-0.4  →  cell_1_2__x-0.4_y-0.4.jpg
cell_1_3:  x=-1.2  y=-0.4  →  cell_1_3__x-1.2_y-0.4.jpg
cell_2_0:  x=-1.2  y= 0.4  →  cell_2_0__x-1.2_y0.4.jpg
```

```
Если огоньков нет:
```

## Обработка ошибок — НИКОГДА НЕ ПАДАЙ

| Ситуация | Действие |
|----------|----------|
| `config.json` не найден | Сообщи пользователю, стоп. |
| Дрон не отвечает (SSH refused/timeout) | Агент попробует 2 раза взлететь. Если всё равно недоступен — агент вернёт ошибку, ты пропускаешь этого дрона и **продолжаешь** с остальными. |
| Survey-дрон не взлетел | Survey невозможен. Всё равно дождись остальных агентов (check-дронов) и собери полный отчёт. |
| Takeoff_land-дрон не взлетел | Пропусти этого дрона, **продолжай** с остальными. |
| `navigate failed` (потеря ArUco) | Агент сам сделает emergency land и вернёт ошибку. Зафиксируй сколько ячеек успел облететь. **Продолжай** — жди остальных агентов. |
| Фото не сохранилось | Агент продолжит облёт. Зафиксируй в отчёте предупреждение. |
| Агент вернул неожиданную ошибку | Ты **продолжаешь** с остальными агентами. |
| Ровер не отвечает на пинг | Не запускай rover-агента. Зафиксируй в отчёте — дроны работают независимо. |
| Ровер не доехал до точки | Rover-агент вернёт ошибку. Зафиксируй в отчёте, дроны продолжают. |

### Главный принцип:

```
Ошибка одного дрона ≠ остановка всей миссии.
Всегда собирай максимум результатов с того что работает.
```

## Важные правила

1. **Ты НЕ запускаешь survey_grid.py и check_drone.py.** Ты даёшь агентам прямые bash-команды к drone_comand/*.py.
2. **Ты сам вычисляешь координаты сетки** по формуле змейки и подставляешь их в задания агентам.
3. **Все агенты запускаются параллельно.** Не жди завершения одного перед запуском другого.
4. **Высота всегда явная.** Для survey — из конфига, для check — всегда 1.5.
5. **Для 1 дрона — только survey-агент**, без check-агентов.
6. **Миссия не падает.** Ошибка одного дрона — не повод останавливать всё. Собери что смог и выведи честный отчёт.
